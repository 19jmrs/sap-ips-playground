# T2 / r1 — Local IPS transformation engine

- Role: backend-developer; outcome: completed implementation with explicitly bounded compatibility.
- Ownership: `src/engine/**`, `tests/engine.test.js`, this report. No other project files edited.

## Delivered

`src/engine/index.js` exports `runPipeline`, `evaluateExpression`, `readPath`, and re-exports the lightweight `supportedFunctions` / `detectEntityPath` catalog. `catalog.js` contains editor metadata without importing evaluator or reference datasets. `dates.js` interprets an explicit set of Java date tokens. `timezones.json` contains 459 ordered SAP/IANA pairs extracted by T1 from the official SAP PDF, preserving first-match ordering.

Three execution modes, selected user/group/role sections, batch envelope detection and editable entity JSONPath, per-entity errors/continuation, source/intermediate/target output, optional mapping trace, conditions, constants, variables, properties, array preservation, optional/default values, all four documented mapping types, operation scope selection, function chaining and array/attribute modifiers are implemented. Target projection syntax `[?(@.attribute)]`, definite paths, wildcard writes/removals, and root copy are supported.

All 27 inventoried mapping function names have executable implementations. `convertLocaleCode` explicitly requires `context.localeMappings`, ordered `[ISO639, BCP47]` pairs from Identity Authentication language master data, because the authoritative public table was unavailable. `resolveEntityIds` uses supplied `context.resolutions`, never remote calls or invented IDs. Missing context fails clearly. Source-generated variables are isolated from target-system variables. `randomPassword` supports a source-less first-function generator and uses Web Crypto with rejection sampling and shuffled constrained character counts.

The five inventoried conditional functions are implemented. Conditions are parsed locally with boolean short circuiting, comparisons, EMPTY, regex, membership/array operators and nested JSONPath filters. JSONPath filters distinguish candidate `@` from root `$`. JSONPath Plus is used with `eval:false` for structural paths; no `eval` or `Function` is used. Prototype-sensitive paths/keys and incorrectly typed writable variable/property names are rejected. Unknown mapping/function/section keys fail explicitly.

## Remaining compatibility boundaries

This is a JavaScript reference interpreter, not SAP's engine or certified full language parity. The exact SAP Jayway version/options, missing-versus-null behavior, singleton details in every context, Java coercion rules, numeric precision, object iteration/order, locale-specific casing and every regex edge are not experimentally certified. `matchRegex` uses JavaScript regex `.test`; whole-string versus substring behavior requires a tenant reference case. Negative lookahead is rejected in line with the documented October 2026 validation change. Several other Java-only regex constructs are rejected; accepted constructs still require differential tests.

Date parsing/formatting supports `yyyy`, `MM`, `dd`, `HH`, `mm`, `ss`, `SSS`, `Z`, `X`, `XXX`, quoted literals and `Date(milliseconds)`, with UTC arithmetic and clamped month/year changes. Other Java patterns fail. Date defaults/timezone behavior beyond these fixtures remains unverified.

Country and subdivision mappings use third-party ISO datasets, which are not proven to match SAP's bundled dataset version or aliases. Unknown values fail. Locale conversion requires the supplied master-data table; timezone conversion uses the extracted complete ordered table but has no tenant differential check. Function modifiers on non-set mapping types and target predicates beyond the supported projection fail instead of producing approximate output. `skipOperations` is rejected because provisioning lifecycle simulation is outside scope. `correlationAttribute` is accepted as transformation metadata; managed-identity correlation and provisioning side effects are not simulated. JSONPath has an explicit supported function set and rejects executable/script expressions.

The engine itself is synchronous. Worker-level timeout/input limits and browser QA belong to coordinator integration; this report makes no standalone denial-of-service guarantee. No payload persistence, network calls, server processing or logging was introduced in the engine. No user choice is needed to integrate these files; outstanding parity checks need anonymized expected-output fixtures, not credentials.
